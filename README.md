# 个人官方网站 PRD
## 1. 项目概述

### 1.1 项目背景

为（喀什大学通信工程 2027 届应届毕业生）构建一个整合个人介绍、项目展示、功能申请、作品架构可视化与管理后台的单页官方网站。核心目标是让访客一站式了解「我是谁、我在做什么、我做过什么、我能做什么、怎么找到我」。

### 1.2 项目目标

- 打造具有空间感、叙事节奏克制、技术感干净的个人官网。

- 展示真实项目「基于轻量化 MobileNetV2 的中药材识别系统」的完整技术架构。

- 提供项目/功能申请入口，并具备本地管理后台进行申请记录、用户、违规举报等管理。

- 所有代码内嵌于单个 HTML 文件，便于直接部署到任意静态服务器。

### 1.3 项目范围

- **交付物**：单个完整 HTML 文件 `index.html`，CSS 与 JavaScript 全部内嵌。

- **部署形态**：纯静态页面，无后端服务，无数据库。

- **数据存储**：浏览器 `localStorage`（演示级前端实现）。

- **响应式**：PC 端（>1024px）内容最大宽度 1200px，手机端（<768px）双栏变单栏，导航栏折叠为汉堡菜单。

- **文件**：`index.html`

## 2. 技术架构

### 2.1 后端语言和框架

**本项目没有后端服务和后端框架。**

当前实现为：

- [x] **纯静态 HTML + 本地存储（localStorage）模拟的后台**

- [ ] PHP（Laravel/ThinkPHP）

- [ ] Java（Spring Boot/JSP）

- [ ] Python（Django/Flask）

- [ ] Node.js（Express/NestJS）

所有业务逻辑、数据校验、权限判断、数据持久化均通过前端 JavaScript 在浏览器端完成。`localStorage` 扮演了"数据库"的角色，页面刷新后数据保留，清除浏览器数据后丢失。

### 2.2 前后端数据交互（AJAX/Fetch）

**本项目不存在 AJAX/Fetch 请求，也没有 RESTful API 或服务端模板渲染。**

由于无后端，所有数据读写通过浏览器本地 API 完成：

| "接口"名称  | 对应前端函数                    | 存储 Key                         | 说明                      |
| ------- | ------------------------- | ------------------------------ | ----------------------- |
| 用户注册    | `performRegister()`       | `users`                        | 写入新用户记录                 |
| 用户登录    | `performLogin()`          | `currentUser` / `adminSession` | 校验密码并创建会话               |
| 管理员申请   | `saveRegistration()`      | `registrations`                | 写入待审批管理员申请              |
| 项目/功能申请 | `saveApplication()`       | `applications`                 | 写入项目/功能申请               |
| 状态变更    | 状态选择器 `change` 事件         | `applications`                 | 修改项目状态                  |
| 作品展示申请  | 作品展示提交逻辑                  | `applications`                 | 更新 `showcaseStatus` 等字段 |
| 违规举报    | `handleReportProject()`   | `applications`                 | 写入举报信息                  |
| 违规处理    | `handleViolationReview()` | `applications`                 | 确认/驳回举报                 |
| 操作日志    | `addAdminLog()`           | `adminLogs`                    | 记录管理员操作                 |
| 邮件通知    | `addUserNotification()`   | `notifications_<username>`     | 给用户发送通知                 |
| 数据备份/恢复 | 导入/导出 JSON                | 文件读写                           | 尚未实现完整功能                |

**RESTful 规范**：不适用。当前"接口"本质是 `localStorage` 的键值对读写函数，非 HTTP 接口。

### 2.3 登录认证机制

**当前采用基于 localStorage 的客户端会话模拟。**

- [ ] 基于 Session（服务端存储，浏览器存 Cookie）

- [ ] 基于 Token（JWT，存储在 localStorage/sessionStorage）

- [x] 前端本地会话：登录成功后将会话信息写入 `localStorage.currentUser`（普通用户）或 `localStorage.adminSession`（管理后台），刷新后读取恢复登录状态。

- [ ] 根本没有登录体系，只是前端路由拦截

登录状态判断函数：`isLoggedIn()` / `getCurrentSession()`，通过检查 `localStorage` 中的会话数据是否存在且未过期实现。

## 3. 页面结构与访问权限

### 3.1 公开前端页面（无需登录）

本项目为单页应用（SPA），所有内容均在 `index.html` 内通过滚动和弹窗切换，不存在真实的 URL 路由。以下板块对所有访客开放：

| 板块       | 说明                                |
| -------- | --------------------------------- |
| 首页（Hero） | 个人定位语、背景动效、向下滚动引导                 |
| 功能板块     | 已有功能展示、新功能申请表单（访客提交后按访客身份记录）      |
| 项目板块     | 预计进行 / 进行中 / 已完成项目列表、项目详情、新项目申请表单 |
| 作品板块     | 作品目录树、Three.js 3D 星图、核心代码片段高亮     |
| 关于我板块    | 个人简介、教育背景、技能标签                    |
| 联系我板块    | 联系方式说明、邮箱一键复制、GitHub 跳转           |
| 导航栏登录入口  | 触发登录/注册弹窗                         |

### 3.2 内嵌管理系统（需要登录）

管理后台同样内嵌在 `index.html` 中，通过 `#admin-section` 区域显示，没有独立的 URL 路径。登录后才可进入：

| 区域/功能     | 可见角色      | 说明                   |
| --------- | --------- | -------------------- |
| 项目/功能管理列表 | 站长、管理员、用户 | 用户只读，站长/管理员可操作       |
| 管理员申请列表   | 仅站长       | 审批/拒绝管理员申请           |
| 用户列表      | 仅站长       | 查看用户、辞退管理员           |
| 举报处理列表    | 站长、管理员    | 确认/驳回违规举报            |
| 操作日志      | 仅站长       | 查看系统操作记录             |
| 个人信息弹窗    | 已登录用户     | 查看/补全信息、提交项目/功能、修改密码 |
| 邮件通知弹窗    | 已登录用户     | 查看个人通知               |

### 3.3 登录保护说明

- 管理后台入口对未登录用户隐藏。

- 各管理功能通过前端角色判断控制可见性，非授权用户即使通过控制台也无法触发受限操作（函数内部有二次权限校验）。

- 由于没有后端，所有前端限制均可被技术手段绕过，因此本实现仅作为演示。

## 4. 功能模块详细说明

### 4.1 全局与导航

- 顶部固定导航栏，包含：首页、功能、项目、作品、关于我、联系我。

- 滚动前透明，滚动后毛玻璃效果加深。

- 当前板块高亮，点击平滑滚动。

- 移动端汉堡菜单。

- 右侧登录/用户菜单入口，已登录显示「用户名 \[权限状态]」及邮件通知红点。

### 4.2 首页（Hero）

- 深色背景 + 动态浮动光晕。

- 主定位语：「用 AI 驱动式开发，让项目真正落地」。

- 副标题：「从需求拆解到部署上线，让 AI 成为开发过程中的核心协作者」。

- 底部「向下滚动」视觉引导动画。

### 4.3 功能板块

- 上方卡片：「已有功能」列表展示。

- 下方卡片：「申请新功能」表单，含功能名称、类型、描述、联系方式。

- 提交后保存到 `localStorage.applications`，标记类型为「功能」。

### 4.4 项目板块

- 上方三张卡片：预计进行 / 进行中 / 已完成项目列表。

- 下方宽卡片：项目详情展示区 + 申请新项目表单。

- 已完成项目详情支持「前往作品查看」，平滑滚动到作品板块并打开对应详情。

- 项目/功能列表均显示「主持人：XXX」。

- 项目详情弹窗内显示主持人 + 参与者卡片。

### 4.5 作品板块

- 作品目录树：完整展示工作区文件结构，可展开/收起。

- 右侧 3D 星图：Three.js + OrbitControls，节点表示文件夹/代码文件。

- 下方详情面板：核心代码片段 + Prism.js 语法高亮。

- 目录树、星图、详情面板三者联动。

- 已发布项目可申请作品展示，上传源文件。

- 已展示作品支持举报（在项目详情内）。

### 4.6 关于我板块

- 个人简介、教育背景、项目经历。

- 个人技能大卡片标签展示。

### 4.7 联系我板块

- 无导航栏，仅说明文字与联系方式。

- 邮箱点击复制，GitHub 点击跳转。

### 4.8 用户系统（登录/注册/忘记密码/锁定）

- **登录弹窗**：用户名、密码、解锁码（TAO 专用）、登录按钮、忘记密码、注册、演示账号登录。

- **注册弹窗**：角色选择（站长/管理员/普通用户）、用户名、密码、联系方式。

  - 站长注册需解锁码 `TAO_ROOT_2026`。

  - 管理员注册进入待审批列表。

  - 普通用户直接注册成功。

- **忘记密码**：TAO 需解锁码，普通用户可直接重置。

- **账户锁定**：连续登录失败 5 次锁定 15 分钟，第 3 次临时锁定后变为永久锁定，需锁定码解除。

- **会话超时**：30 分钟无操作自动退出。

- **演示账号登录**：一键填充 TAO 账号，跳过首次登录改密弹窗。

### 4.9 个人中心

- 显示用户名、权限状态、联系方式。

- 展示用户参与/主持的项目/功能列表。

- 提交已有项目/功能表单：

  - 类型选择（项目/功能）。

  - 「信息补充」选项：勾选后选择已有项目/功能，填写补充信息，跳过重复检测。

  - 名称、描述、项目预期/目标（正常申请时必填）。

  - 新参与人员输入。

  - 文件上传（图片或 ZIP，≤50MB）。

- 忘记密码按钮。

- 注销账户按钮。

- 违规记录区域常驻显示。

- 演示账号登录时显示黄色警告标识。

### 4.10 管理后台

- **管理员申请列表（站长）**：显示申请人、联系方式、申请角色、状态、申请时间，支持批准/拒绝。

- **用户列表（站长）**：显示用户名、联系方式、权限等级、注册时间，支持辞退管理员。

- **项目/功能管理列表（站长/管理员/用户）**：

  - 显示类型、名称、分类、负责人、联系方式、文件、提交时间、状态。

  - 站长/管理员可修改状态、批准/退回作品展示、删除项目。

  - 普通用户只读。

  - 站长/管理员可清空全部项目/功能申请。

- **举报处理列表（站长/管理员）**：显示举报项目、负责人、举报人、理由、状态，支持确认/驳回。

  - 站长/管理员可清空违规记录。

- **操作日志（站长）**：记录所有管理员操作，支持清空。

- **恢复默认数据（站长）**：清空 localStorage 并恢复默认 TAO 账号。

### 4.11 邮件通知系统

- 导航栏用户下拉菜单新增「邮件通知」选项。

- 未读通知显示小红点与数量。

- 弹窗显示该用户最近 5 条通知，超出清除最早记录。

- 查看后标记已读。

- 触发场景：项目状态变更、作品展示审批/退回、违规举报确认/驳回、项目被删除、管理员被辞退等。

### 4.12 状态流转

项目/功能状态顺序：`待处理 → 处理中 → 已发布 → 已退回`。

- 从某状态开始后，不能再选择前置状态。

- `已发布` 后除非用户主动撤回，否则任何用户不能再选择状态。

- `已退回` 后完全锁定。

- 已退回的项目/功能可重新申请。

### 4.13 举报与违规处理

- 已发布项目/功能可在详情内举报。

- 访客举报仅记录；用户举报进入违规处理列表。

- 站长/管理员可确认（项目自动退回）或驳回（需理由）。

- 驳回后允许再次举报；确认后不可再次举报。

- 被举报人/举报人通过邮件通知接收处理结果。

## 7. 安全说明

- 所有数据仍存储在浏览器 `localStorage` 中。

- 已采取的安全措施：

  - 密码与解锁码使用 SHA-256 + 随机盐哈希存储。

  - 用户输入使用 HTML 转义（`escapeHtml`）防止 XSS。

  - 联系方式按角色脱敏显示。

  - 添加 CSP 策略。

  - 操作日志记录敏感操作。

- **重要提示**：浏览器本地存储无法达到服务端数据库的安全级别，所有前端权限限制均可被技术手段绕过。正式上线必须迁移到后端认证与持久化存储。

## 8. 验收标准汇总

### 8.1 登录与注册

- 访客可通过导航栏登录按钮打开登录/注册弹窗。

- 站长注册必须输入正确解锁码。

- 管理员注册进入待审批状态。

- 普通用户注册后直接可用。

- 连续失败 5 次触发锁定，15 分钟后自动解锁或永久锁定需锁定码。

### 8.2 项目/功能管理

- 用户可提交新项目/功能或补充已有项目/功能。

- 重复提交相同/相似项目时给出提示；被退回后可重新申请。

- 站长/管理员可修改项目状态，状态按既定顺序流转。

- 用户可在个人信息中撤回已发布项目。

### 8.3 作品展示与举报

- 已发布项目可申请作品展示。

- 站长/管理员可批准或退回作品展示申请。

- 已发布项目详情内可举报。

- 举报确认后项目自动退回；驳回后可再次举报。

### 8.4 管理后台

- 站长可查看所有菜单并执行所有操作。

- 管理员只能看到项目/功能管理和举报处理。

- 用户只能看到项目/功能列表（只读）。

- 站长/管理员不能处理自己的项目/功能/举报/申请。

### 8.5 通知与日志

- 项目状态变更、作品展示审批、违规处理、删除项目等操作给相关用户发送邮件通知。

- 未读通知在导航栏显示红点与数量。

- 操作日志记录所有管理员操作，仅站长可见。

### 8.6 数据与部署

- 单 HTML 文件即可运行。

- 数据存储在浏览器 `localStorage`。

- 清除浏览器数据后恢复默认 TAO 账号（通过「恢复默认数据」按钮或首次加载）。

| 有哪些 API 接口？  | 无 HTTP API，数据交互通过 localStorage 读写函数完成                  |
| 是否 RESTful？  | 否，无后端服务                                                |
| 前端承担了哪些业务计算？ | 表单校验、密码哈希、文件校验、状态机、权限菜单生成、通知管理                         |
| 如何判断登录？      | 检查 localStorage 中的 `currentUser` / `adminSession` 会话对象 |
